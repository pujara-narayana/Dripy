────────────────────────────────────────
WHAT IT WOULD TAKE FOR REAL USERS
────────────────────────────────────────

The core architecture holds up: the agent, the tools, the safe payment flow, the iMessage
bridge and the fallbacks. The gaps:

Area: Buying the item ⚠️ biggest gap
What's demo-only today: Stripe charges your card, but nothing actually orders the jacket from Zara
What real use needs: A way to actually complete the order: (a) send the user to the store to check out (simplest, and earns affiliate fees), (b) the newer agent-checkout
standards (Visa Intelligent Commerce, Stripe/OpenAI's Agentic Commerce Protocol, Shopify), which need each merchant to support them, or (c) Dripy buys on the user's
behalf, which means fulfillment, returns and money-transmission law
Effort: (a) days; (b) weeks plus partnerships; (c) months
────────────────────────────────────────
Area: Users and login
What's demo-only today: One hardcoded demo user. Any unknown phone number gets Alex's closet, which would leak data in production. user_id is a plain request parameter.
What real use needs: Sign-up by phone number, login for the web app, user identity taken from the session, and database-level security rules per user
Effort: 2–4 days
────────────────────────────────────────
Area: Saving cards
What's demo-only today: A test card attached automatically
What real use needs: Card entry in the app (Stripe's card form); handling banks that demand extra verification on background charges; refunds
Effort: 2–3 days
────────────────────────────────────────
Area: Getting the closet in
What's demo-only today: Gmail read-only works for one test user (refresh token in env, expires every 7 days in testing mode); otherwise 5 seeded emails; wear counts are seeded
What real use needs: Per-user Gmail OAuth with stored tokens, Google's paid security review for public users (weeks), Outlook, product photos, de-duplication, and a way to log
what you actually wear
Effort: 1–2 weeks, plus Google's review
────────────────────────────────────────
Area: Product results
What's demo-only today: SerpAPI (scrapes Google, about $0.025 per search) plus curated demo matches; Lens times out often; live matches lack a store domain
What real use needs: Licensed product feeds (ShopStyle, Rakuten, Impact), live stock and sizes, cost limits per user
Effort: 1 week
────────────────────────────────────────
Area: iMessage
What's demo-only today: Free plan, shared number; every user must be pre-registered; WhatsApp not enabled
What real use needs: Photon Business plan with a dedicated number (paid), opt-in and STOP handling, the worker running 24/7, a real single-worker lock (today it only checks a local port)
Effort: Days, plus cost
────────────────────────────────────────
Area: Reliability
What's demo-only today: Synchronous requests, no queue; a slow Gemini or Lens call makes the whole reply wait
What real use needs: A job queue with retries, model fallback, usage limits per user, monitoring and alerts
Effort: 3–5 days
────────────────────────────────────────
Area: Security and privacy
What's demo-only today: Image-URL fetch is now SSRF-safe; otherwise fine for a demo
What real use needs: Data deletion, a privacy policy, encryption of emails and purchase history, and a broader security review
Effort: 1 week
────────────────────────────────────────
Area: Donations
What's demo-only today: Geoapify (OpenStreetMap second-hand shops) + 5 seeded Seattle stores; charity chains only from the seeded list
What real use needs: A source with good charity/donation coverage and accurate hours (Google Places, paid), per-city data
Effort: 1 day
